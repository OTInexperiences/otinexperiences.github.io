<h3>Paths</h3>
In OTWorkbench a path is a sequence of points (or Vertices).  OTWorkbench assumes that any two consecutive Vertices are connected by a straight line. By placing the points close together we can approximate most curves.

<figure class="wp-recovered-caption">
<a href="/assets/placeholder-original-image.svg"><img alt="" class="size-medium wp-image-485" height="139" src="/assets/placeholder-original-image.svg" title="path2" width="300"/></a>
<figcaption>A path is a collection of vertices</figcaption>
</figure>

Paths may also be segmented so that two consecutive points are not considered to define a line. In this case the first point denotes the end of the current segment whilst the next point denotes the start of the next segment.

<h3>Vertex state</h3>
Each vertex has a state which may be either
<ol>
<li>VISIBLE  - a visible point is used as the starting point for a cutter move.  OTWorkbench will generate the G code to make a linear cut between two visible points.</li>
<li>HIDDEN - a hidden point takes no part in the machining process and is ignored by the G code generator.  A point may become hidden if it lies within a masked area.  All hidden points may be snipped out of the path thus leaving a collection of visible segments. In the image above hidden</li>
<li>UP  - this denotes that the point is either a) the end of the current segment or (b) the transition  point (usually an area boundary) after which points on the path are hidden. It is also an instruction to the G code generator to move the cutting head up to the safe height from the current cutting depth.</li>
<li>DOWN - this denotes that the point is either a) the start of a new segment or b) the transition point (again usually an area boundary) after which points become visible again. It is also an instruction to the G code generator to move the cutting head down from the safe height to the workpieces upper surface and then to make a linear move at a given feed rate down to the current cutting depth.</li>
</ol>
In the image above visible points are shown black, hidden points are gray,  up points are red and down points are green.
The process of snipping a path is just one of removing all hidden points leaving just the visible ones together with the boundary points UP/DOWN acting as segment markers.  Snipping a path is permanent, hidden points cannot be recovered.

<div>Each vertex has an associated coordinate value giving its position in space. Coordinates can be inspected but not changed using the vertexinspector.</div>
<div>This shows</div>
<div>
<ol>
<li>The index number of the point in the path sequence</li>
<li>The X coordinate of the point</li>
<li>The Y coordinate of the point</li>
<li>The Z coordinate of the point</li>
<li>The point's state represented by the V,H,U,D</li>
<li>If the point is an <a href="http://blog.alanbattersby.co.uk/action-points-and-action-blocks/" target="_self">action point</a> it is marked by a red asterisk.</li>
</ol>
</div>

<h3>Path Transformations</h3>
The position, size and orientation of a path may be altered by applying a<a href="{{ '/software/ornamental-turning-workbench/paths/transformations/' | relative_url }}"> transformation </a>to the path.  For example a phase change in standard OT is really just a rotation of the path.
